# 하이록스 맵 — 검수(MODERATION) 가이드

운영자·검수자가 사용자 제보를 승인/반려할 때 사용하는 체크리스트입니다.

## 1. 원칙

- **아무나 즉시 공개 등록 불가** — 모든 커뮤니티 제보는 검수 후 `published_at` 설정.
- **증빙 없으면 승인 불가** — 예외 없음 (운영자 직접 현장 확인 시 메모 필수).
- **공식 클럽 정보**는 [HYROX 한국](https://hyroxsouthkorea.com/ko/%ED%95%98%EC%9D%B4%EB%A1%9D%EC%8A%A4-%EC%B2%B4%EC%9C%A1%EA%B4%80-%EC%B0%BE%EA%B8%B0/) 우선. 충돌 시 공식 목록이 맞으면 제보 수정 요청.

---

## 2. 제보 상태 전이

| 상태 | 의미 | 운영자 액션 |
|------|------|------------|
| `submitted` | 제출 완료, 대기 | 큐에서 `in_review`로 이동 |
| `in_review` | 검수 중 | 승인 / 반려 / `needs_info` |
| `needs_info` | 보완 요청 | 제보자 연락 후 재제출 대기 |
| `approved` | 승인 → Venue 생성 | `trust_level` 부여 후 공개 |
| `rejected` | 반려 | `moderator_note` 필수 |

---

## 3. 자동 1차 검증 (시스템)

다음 항목은 API/서버에서 자동 처리합니다.

- [ ] 필수 필드: 시설명, 주소, 위도/경도, `venue_type`, 체험 서술, 태그 1개 이상, 증빙 URL 1개 이상
- [ ] 중복: 동일 주소 반경 **50m** 이내 기존 `Venue` 또는 `pending` 제보 존재 시 플래그
- [ ] 금칙어 필터 (욕설, 명백한 스팸 URL)
- [ ] Rate limit: IP/세션당 일 **3건** 제보

자동 플래그만으로는 반려하지 않고, 운영자 큐에 **우선 검토** 표시.

---

## 4. 운영자 2차 체크리스트

### A. 시설 실재·식별

- [ ] 네이버/카카오 지도에 동일 상호·주소 존재
- [ ] 상호·주소가 제보 내용과 일치
- [ ] 폐업·이전 의심 시 → `needs_info` 또는 반려

### B. 시뮬레이션 가능성 (핵심)

| 태그 | 확인 방법 |
|------|----------|
| `sled_push` | 슬레드 푸시 레일·카펫·장비 사진 |
| `sled_pull` | 슬레드 풀 레일·로프·장비 사진 |
| `sandbag_lunge` | 샌드백·런지 구간 사진 또는 안내 |
| `sled_push_pull` | (레거시) 푸시·풀 통합 표기 — 신규 제보는 분리 권장 |
| `outdoor_run` | 야외 코스 설명 + 거리/왕복 횟수가 구체적인지 |
| `ski_erg` / `rower` | 장비 사진 또는 수업 커리큘럼 |
| `full_stations` | 8스테이션 전부 가능하다고 주장 시 증빙 2종 이상 권장 |

- [ ] 체험 서술과 선택 태그가 **논리적으로 일치**
- [ ] “풀 시뮬 매주 가능” 등 과장 표현 → 서술 수정 요청 또는 태그 축소

### C. 증빙 품질

- [ ] 사진이 해당 시설 내부/장비로 보이는지 (스톡·타 gym 사진 의심)
- [ ] 예약/인스타 캡처 URL이 유효한지
- [ ] 증빙만으로 부족하면 `needs_info` — 추가 사진 1장 요청

### D. 공식 클럽 중복

- [ ] 이미 `source: official` 인 Venue가 있으면 → 제보를 **merge** 또는 반려(중복)
- [ ] 공식 클럽인데 `trust_level`이 community만 있는 경우 → `official`로 상향

### E. 드랍인·가격

- [ ] 드랍인 가능 표기 시 비용·요일이 있으면 신뢰도 상승
- [ ] 확인 불가 시 “문의 필요”로 상세 필드 비움 (허위 가격 금지)

---

## 5. 승인 시 부여 규칙

| 조건 | `trust_level` | `source` |
|------|---------------|----------|
| HYROX 공식 클럽 목록 일치 | `official` | `official` |
| 증빙 충분 + 운영자 확인 | `verified` | `community_report` |
| 증빙 최소 충족, 태그 일부만 확인 | `community` | `community_report` |

`published_at` = 승인 시각. `pending` Venue는 지도 API에서 제외.

---

## 6. 반려 사유 템플릿

| 코드 | 제보자 안내 문구 (예시) |
|------|------------------------|
| `DUPLICATE` | 이미 등록된 시설입니다. |
| `NO_EVIDENCE` | 시뮬레이션 가능 여부를 확인할 수 있는 사진이 필요합니다. |
| `MISMATCH` | 주소/상호가 확인되지 않습니다. 정확한 정보로 다시 제보해 주세요. |
| `OVERCLAIM` | 선택하신 장비/코스가 확인되지 않습니다. 실제 가능한 항목만 선택해 주세요. |
| `SPAM` | 제보 정책에 맞지 않아 반려되었습니다. |

---

## 7. 다중 제보 · 병합 (v1.1)

- 동일 시설 제보 2건 이상: **최신·증빙 품질 높은 건**을 기준으로 merge
- 상충 정보(야외런 유무 등): `needs_info` 후 제보자 1명에게 확인
- merge 후 기존 Report는 `merged_into_venue_id` 기록

---

## 8. 신고 처리 (지도 공개 후)

- 사용자 신고 → 해당 Venue `flagged` → 48시간 내 재검수
- 3건 이상 동일 이슈 → 일시 비공개(`published_at` null) 후 현장/전화 확인

## 10. Admin 작업 순서 (권장)

1. `/admin/reports` 큐 — `submitted` 오래된 순
2. 지도·네이버·증빙 탭 병렬 확인
3. 승인 → Venue 자동 생성 확인 → `/venues/[slug]` 미리보기
4. 반려/보완 시 `moderator_note` 저장 (내부용 + 제보자용 분리 권장)
